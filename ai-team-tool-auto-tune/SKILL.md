# AI 多 Agent 协同 — 自我优化工具

## 触发

由编排 PM 与各角色 skill 引用。

## 优化原则

**静默优先**：流程通畅则无输出，仅在有问题时记录建议。

## 各角色自检

### 角色 Agent 自检时机

每个角色 Agent 在向 PM 发送完成信号前，自检以下情况：

| 自检项 | 判定标准 |
|--------|----------|
| Skill 规则缺失 | 是否因缺少规则导致反复试错 ≥ 3 次？ |
| 门禁过严/过松 | 置信度是否卡在 ~85% 附近难以突破？ |
| 选项列表不足 | 预设选项是否未覆盖实际场景？ |
| MCP LSP 反复报错 | 同一类错误是否出现 ≥ 3 次？ |

### 记录方式

- **流程通畅、置信度 > 85%** → 静默，不记录任何建议
- **置信度卡在 85% 附近或有明显阻碍** → 在 send_message 中附带优化建议：

```
send_message(
  type="message",
  recipient="main",
  content="角色完成 | 置信度:{XX}% | ... | 优化建议：{简要描述}"
)
```

## PM 汇总

PM 知道自己作为编排者，负责收集各角色的优化建议。

收到所有角色完成信号后，收集优化建议，附在最终交付报告末尾：

```markdown
## Skill 优化建议

| 来源角色 | 问题 | 建议 |
|----------|------|------|
| coder | MCP LSP check 反复失败3次 | 补充 MCP 初始化后的验证步骤 |
| （空则无此章节） |
```

同时，PM 自身也自检：流程编排是否合理、门禁检查是否有效、用户兜底是否触发过等。

## 自动更新 CHANGELOG

修改 ai-team-* 体系 skill 后，自动更新仓库根目录的 `CHANGELOG.md`：

- 日期标题新日期置顶
- 当天改动按时间正序追加序号
- 跨天重新编号

> 使用 `update_memory` 写入记忆体记录此规则，后续对话自动生效。

## 禁止事项

| ❌ 禁止 | ✅ 正确 |
|---|---|
| 流程通畅时提问用户 | 静默，仅在交付报告末尾附带 |
| 自行修改 Skill | 只记录建议，由用户决定是否采纳 |
| 每个角色都输出建议 | 仅置信度 < 90% 且有明显阻碍时才记录 |
