# 测试用例接入与计划

> **职责边界**：本 skill 只做 **解析 + 计划**（产出用例集与计划文档）。**执行手段与命令由平台执行驱动 skill 提供**（鸿蒙为 `{platform_map}` 的「执行驱动」列所指 skill），本文件不内联任何设备 / 框架 / 平台命令。

## 触发

满足任一即加载：用户提供用例文档或用例清单要求照此验证；需把用例清单转成可执行计划。

## 一、解析用例原文档

**[门禁] 直接读原文件，不要求用户改格式**：来源可能是 Excel / CSV / Markdown / 纯文本 / 聊天口述，自行选择解析方式。
非文本格式（如 `.xlsx`）先转成可读文本再解析，转换手段不限，但**转换后必须回读校验**（见 1.2）。

### 1.1 字段按语义映射

**[门禁] 列名不固定，禁止要求用户改表**：

| 语义字段 | 常见列名（任一命中即采用） |
|----------|---------------------------|
| ID | 用例编号 / ID / No. / 序号 / 用例标识 / Key / 用例Key |
| 标题 | 用例名称 / 标题 / 场景 / 功能点 |
| 前置条件 | 前置 / 前提 / 预置条件 / 环境要求 |
| 步骤 | 操作步骤 / 步骤 / 操作 / 执行步骤 |
| 预期结果 | 预期结果 / 期望结果 / 预期 / 验收标准 |
| 优先级 | 优先级 / 级别 / P0-P3 |

| 情形 | 处理 |
|------|------|
| 命中多个同类字段 | 合并保留原文，**不猜测哪个是主列** |
| 无法映射的列 | 原样留在「备注」，**不得丢弃** |
| 同一用例跨多行（合并单元格 / 多步骤分行） | 按 ID 或上下文**归并为一条**，并记录归并条数 |
| 聊天口述 | 先复述成用例集草稿，再请用户确认 |

#### 1.1.1 **[门禁] 标识与分层编号**

| 情形 | 处理 |
|------|------|
| 纯数字（`16558`） | 原样沿用 |
| 非纯数字 / 复合（`云盘-001`、`TC_16558`、`16558-1`） | **原样沿用**，不重编号、不做类型转换，仅用于引用与结果回填 |
| 无任何标识 | `TC-{序号}` |
| 同文档内标识重复 | 追加来源位置消歧 `{id}@{行号}`，并列入待澄清清单 |
| **条目内分层编号**（`1.` → `1.1` → `2.3.1`） | **必须解析出层级**；步骤与预期结果按**同层级前缀挂靠**（`2.3` 对 `2.3`、`1.` 对 `1.`）。**两列条数不等是常态**（实测某条：步骤 5 条 / 预期 13 条），**禁止按行序强行一一对应**；原文无编号时按行序对位，并在文末标注「对位不确定」 |

### 1.2 **[门禁] 回读校验**

解析完先统计三项并向用户确认：**用例总条数 / 缺字段条数 / 归并条数**。
条数不一致 → 列出差异再问；**禁止自行补全，禁止用 AI 生成内容填充人工用例**。

## 二、产物 1：规范化用例集

写入 `${artifact_dir}/test-cases.md`（`{任务标识}` = 来源文件名 slug + `-YYMMDD`；用户另有指定则以指定为准）：

```markdown
# 测试用例集
- 来源文件：{原始文件路径}
- 解析时间：{ISO timestamp}
- 用例条数：{N}（缺字段 {n1} 条 / 归并 {n2} 条）
```

| 列 | 要求 |
|----|------|
| ID | 沿用原文编号；原文无编号 → `TC-{序号}` |
| 标题 | 原文标题；过长可压缩但保留关键词 |
| 前置条件 | 原文；缺失标「原文未给」 |
| 步骤 | **逐条保留原文步骤**，不得概括改写 |
| 预期结果 | **逐条保留原文**，不得新增 / 删除 / 放宽 |
| 优先级 | 原文；无则留空 |
| 原文位置 | `{文件}#{sheet / 行号 / 标题}` —— 供回溯与争议定位 |

**[门禁] 只做结构归一，不改用例语义**：允许字段对齐、去合并、拆多步骤；**不得修改预期结果、不得新增或删除用例**。
发现原文矛盾 / 重复 / 歧义 → 集中列「待澄清清单」，**一次** `ask_followup_question` 问清，不自行裁决。

## 三、产物 2：测试用例计划

写入 `${artifact_dir}/test-plan.md`。计划 = 把用例集转成**可逐条执行**的序列。

### 3.1 逐条标注执行元数据

| 列 | 取值 |
|----|------|
| ID / 标题 | 引用 `test-cases.md` |
| 执行手段 | 自动化-单测 / 自动化-设备驱动 / 人工交互 / 静态比对 / 不可覆盖 |
| 前置条件 | 需设备 / 账号 / 数据 / 环境条件的项（含原文出处） |
| 判定方式 | 该条判「通过」靠什么断言（界面节点 / 日志标记 / 返回值 / 用户确认） |
| 批次 | 见 3.2 |

> 执行手段**具体用哪条命令、哪个工具链**由执行侧 skill 提供；本表只定「用哪一类手段」。

### 3.2 **[门禁] 批次切分：默认串行**

**默认同一时刻只跑一条用例**。真实设备通常只有一台，且用例间共享登录态 / 进程 / 日志缓冲 —— 并行会让断言看到别人的界面、日志与操作对不上号。

仅当**三个条件同时满足**才可分批并行：

| 条件 | 说明 |
|------|------|
| 无共享状态 | 不共享账号 / 数据 / 进程 / 页面位置 |
| 可独立起停 | 任一条失败不影响其他条，无需按序恢复环境 |
| 证据不串线 | 每条证据来源可分离（各自进程 / 各自日志过滤） |

| 规则 | 说明 |
|------|------|
| 不满足 → 串行 | 顺序上「不改变环境」的用例排前 |
| **[门禁] 环境破坏类最后集中执行** | 断网 / 清数据 / 切账号 / 杀进程等会污染后续用例 |
| 并行仍逐条取证 | **禁止以「同一批都跑了」代替逐条断言**；并行方案须经用户确认后再执行 |

### 3.3 **[门禁] 环境依赖聚合：一次问清**

把「需用户物理操作」的用例聚合为**一张清单**：

| 列 | 说明 |
|----|------|
| 操作 | 用户要做什么（关 Wi-Fi / 授权 / 解锁 / 登录某账号 / 清理数据） |
| 涉及用例 | 用例 ID 列表 |
| 副作用 | 对设备与用户的影响（如来电中断） |
| 生效校验方式 | 怎么确认条件真的生效 |
| 恢复方式 | 怎么恢复、如何复核 |
| 不可用时的降级 | 替代手段或记为未覆盖 |

设计期**一次** `ask_followup_question` 说明全部操作；**禁止每条用例各问一次**。

**[门禁] 固定必列项**（每次都要检查，缺项不得进入执行）：

| 类别 | 问什么 |
|------|--------|
| 应用定位 | bundleName（**由用户提供**，不自行按关键词猜应用） |
| 登录态 / 账号 | 是否已登录、账号等级（会员 / 非会员）、剩余权益次数 |
| **破坏性数据操作** | **列出具体破坏项让用户勾选**（置顶 / 移动 / 删除 / 重命名 / 新建 / 上传…）；**未勾选项记未覆盖**，不得默认允许 |
| 不可逆权益消耗 | 单独确认（如扣减次数、切换后不可回退） |
| 第三方应用依赖 | 设备是否已装并登录（如微信） |
| 服务端数据 / 配置 | 目标数据是否具备（不具备 → 记未覆盖，不得伪造通过） |
| 网络状态 | 是否需断网 / 弱网类（执行序放最后） |

> 破坏性操作、登录态、粒度选择**合并进「计划确认」那一次询问**，不另起一轮。

> 与用户协同的判据、交互模板与**选项按钮规范**见 `ai-team-qa-tool-workflow` §二（含：何时该问用户 / 问了必校验 / 必须恢复）。

### 3.4 不可覆盖项

手段不支持（如短时弹窗采样窗口不足）或用户不便配合的项 → 计划内标 `不可覆盖 + 原因`；执行期如实登记，**禁止伪造通过**。

### 3.5 **[门禁] 执行粒度选择与用时粗估**

计划产出后，向用户给出执行粒度选项，**并附预计用时**：

| 选项 | 含义 |
|------|------|
| 全量执行 | 计划内全部用例、逐子项执行 |
| 按批次执行 | 按 §3.2 批次逐个推进，可中途叫停 |
| 仅高优先级 | 只跑 P0 / P1 |
| 抽样精简 | 主链路必跑 + 每条抽 N 个关键子项（须列出未覆盖子项） |

**用时粗估口径**：`用例条数 × 单条平均耗时 + 跨用例导航与取证开销`

| 规则 | 说明 |
|------|------|
| 取值来源 | 单条平均耗时**取上一轮同类实测值** |
| 无样本时 | **必须标注「粗估」**，不得写成承诺值 |
| 抽样精简 | 按 `实际子项数 / 总子项数` 折算，并向用户说明哪些子项未覆盖 |

## 四、**[门禁] 计划确认后才执行**

展示下表后由用户确认；粒度选项见 §3.5，即 `["全量执行", "按批次执行", "仅高优先级用例", "抽样精简执行"]`（末位自定义项按 `ai-team-qa-tool-workflow` §2.1「选项规范」统一追加）：

| 展示项 |
|--------|
| 用例总数 / 可自动化条数 / 需用户操作条数 / 不可覆盖条数 |
| 批次安排（串行顺序 / 并行分组）与**用时粗估**（无实测样本时标明「粗估」） |
| **破坏性操作待勾选清单**（未勾选 → 记未覆盖） |
| **登录态 / 账号与权益**待确认项 |
| 待澄清清单 —— **未澄清项不得进入执行** |

## 五、判定与降级

| 情况 | 处理 |
|------|------|
| 解析出 0 条用例 | **阻塞**：回问用户文件是否正确 / 是否需要另行提取 |
| 存在无法映射的列且语义不明 | 列出「无法映射列 + 原文样例」问用户，不猜测 |
| 用例之间矛盾 / 重复 | 列「待澄清清单」一次问清，**不自行合并** |
| 用户只提供部分用例 | 按实际范围出计划，报告标注「用例来源不完整」 |
| 用例需人工判定（如观感类） | 标「人工交互」并由用户确认，**不得由 AI 代填结果** |
| 用例数与实现范围对不上 | 记入报告「需求覆盖缺口」，交用户裁决，不自行增删用例 |

## 六、配置

```yaml
output_dir: "{artifact_dir}"
cases_path: "{output_dir}/test-cases.md"
plan_path: "{output_dir}/test-plan.md"
default_batch_mode: serial      # 串行基线；并行须同时满足 §3.2 三条件并经用户确认
```
