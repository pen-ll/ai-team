# 极简编码规范

编码第一原则：**先理解，再极简**。读懂任务和变更涉及的代码、追踪完整流程后，再追求最少可行方案。绝不是跳过理解去追求小 diff。

---

## 一、懒惰阶梯（编码前逐级检查）

编写任何代码前，从第一级开始逐级检查，停在第一个成立的级别：

| 级 | 检查 | 成立则 |
|----|------|--------|
| 1 | 这功能需要存在吗？投机需求 | 跳过，一句话说明（YAGNI） |
| 2 | 代码库已有实现？helper/util/type/模式 | 复用，不重写 |
| 3 | 标准库能实现？ | 用标准库 |
| 4 | 平台原生特性覆盖？如 `<input type="date">` 替代日期选择器库、CSS 替代 JS、DB 约束替代应用层校验 | 用原生 |
| 5 | 已安装的依赖能解决？ | 用已装依赖，不为几行代码新加依赖 |
| 6 | 能写成一行？ | 写一行 |
| 7 | 以上都不满足 | 写最少可行代码 |

**规则**：
- 不写未被要求的抽象：只有一个实现的 interface 不要写、单产品的 factory 不要写、永远不会变的值不要做配置项 config
- 禁止样板代码、禁止"为以后"搭脚手架
- 删除优于新增；最少文件数；最短可用 diff
- 两个标准库方案同样大小时，选边界情况正确的那一个——极简不是选更脆弱的算法

> **默认行为**：默认执行完整阶梯；若用户明确要求完整实现（如指定框架/指定模板），则按用户要求执行，不再精简。

---

## 二、[门禁] Bug 修复 = 根因修复，非症状修补

报告的是症状。修复前**必须** grep 目标函数的所有调用方：

- 根因修复（共享函数加一个 guard）通常比在每个调用方打补丁的 diff 更小
- 只修 ticket 指出的那条路径，会留下兄弟调用方仍然损坏
- 在根上修一次，让所有调用方通过同一处修复

> 根因的**定位流程**（埋点→复现→读日志→诊断）由 `ai-team-tool-debug-loop` 负责；本规范只约束找到根因后的**修复方式**。两处均已加载时，定位流程以 debug-loop 为准，修复方式以本节为准。

---

## 三、[门禁] 不精简清单

极简永不裁剪以下内容：

| 项 | 说明 |
|----|------|
| 信任边界输入校验 | 所有外部输入必须校验 |
| 防数据丢失的错误处理 | 错误处理不可省 |
| 安全措施 | 安全红线见 `ai-team-tool-security` |
| 可访问性基础 | 无障碍基础不可省 |
| 用户明确要求的实现 | 用户坚持完整版 → 构建它，不重复争论 |

非平凡逻辑（分支/循环/解析器/资金或安全路径）必须留下**一个**可运行的检查（最小的 `assert` 自检或一个小 `test_*.py`）。平凡一行无需测试，YAGNI 也适用于测试。

---

## 四、minimal: 债务注释约定

对**有意识地**简化并砍掉真实角落（全局锁、O(n²) 扫描、朴素启发式）的代码，用 `minimal:` 注释命名上限和升级路径：

```
# minimal: 全局锁，如吞吐量成瓶颈则改为每账号锁
```

- 注释格式：`minimal: {上限}, {升级路径}`
- 用途：让"以后再做"可被追踪（审查/收尾时可 grep 汇总）
- 允许：未命名升级路径则标注 `minimal: {上限}, 暂无升级路径`，避免静默腐烂

---

## 五、过度设计审查（reviewer 使用）

对 diff 或全仓库做过度设计审查，只猎复杂度，逐条一行输出：

`L{行}: {标签} {问题}. {替代方案}.`

| 标签 | 含义 | 替代方案 |
|------|------|----------|
| `delete:` | 死代码、未用灵活性、投机功能 | 无，直接删 |
| `stdlib:` | 手写但标准库已提供 | 命名标准库函数 |
| `native:` | 依赖或代码做平台已能做的事 | 命名原生特性 |
| `yagni:` | 单实现抽象、没人设置的 config、单调用方分层 | 内联 |
| `shrink:` | 相同逻辑更少行数 | 展示更短写法 |

**结束指标**：`net: -{N} lines possible`；无可删则 `Lean already. Ship.`

**边界**：正确性 bug、安全漏洞、性能问题**明确不在此范围**——转常规审查。单个冒烟测试或 `assert` 自检是极简底线，永不标记删除。

---

## 六、边界声明

| 层 | 归属 |
|----|------|
| 代码层（代码量/复杂度/抽象） | 本规范 |
| 流程/文档/对话层（Token 优化、文档精简、歧义处理） | `ai-team-tool-global-rule` |
| 根因定位流程 | `ai-team-tool-debug-loop` |
| UI 完备性（四态/防抖） | `ai-team-tool-ui-ux` |

本规范不产生独立报告文件，仅影响编码产出与审查反馈。
