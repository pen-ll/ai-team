# 测试领域 — 实现者扩展（`qa` · 原型 maker · 变体 runner）

## 触发

领域=qa 且变体=runner 时经「第零步：领域适配」启用。**不单独 spawn**，仅补全/覆盖基座中标 `[领域扩展]` / `[特化]` 的步骤。

## 覆盖范围

| 基座位置（`ai-team-role-maker`） | 本扩展的作用 |
|---------------------------------|-------------|
| 第零步-A 特化适配 | 按 `platform-map.md` 按需加载「环境事实」与「执行驱动」（见 §一） |
| 第零步-B 返工模式分流 | **不适用**（缺陷修复属开发领域，本领域不编译产品代码） |
| 第一步 读取上游 | 上游 = `test-plan.md`（见 §二） |
| 第一步-A 输入校验 | 追加测试必读产物校验（见 §二） |
| 第一步-B 清单式分批产出 | **覆盖为逐条执行**：按计划逐条执行 + 逐条独立取证（见 §三） |
| 第三步 实现方案确定 | **跳过**（测试无技术选型） |
| 第四步 产出 | 提供执行编排、取证与缺陷登记规则（见 §三 ~ §五） |
| 第五步 产物验证 | **覆盖为结果回填校验**（见 §六） |
| 第六步 产出报告 | 路径改为 `{artifact_dir}/test-report.md`（见 §七） |
| 第七步 置信度评估 | 追加测试专属检查项（见 §八） |

## 一、平台适配（按需加载，不提前）

1. `read_file("{platform_map}")` → 匹配当前 `platform`
2. 命中 `harmony` → 按需 `use_skill`：
   - **环境事实** `ai-team-dev-pt-hm-env`：需要 CLI 能力自检 / 设备确认 / 安装启动 / 日志抓取时加载
   - **执行驱动** `ai-team-dev-pt-hm-ui-test`：需要真机 UI 驱动与运行时取证时加载（命令表 / 节点树约定 / 等待策略 / 网络用例）
3. 未命中 → 按映射表「未命中平台」处置（`ask_followup_question` 给选项），**不得默认套用鸿蒙流程**

> **[门禁] 缺口按映射表登记**：`platform-map.md`「已知缺口」列的 6 项（报告落盘写死 / 前置准备面向构建产物 / 无应用定位命令 / 无测试侧错误码表 / 无环境异常总表 / 无设备工具链来源解析）在本领域**均需按该表处置**；因缺口导致某项无法验证 → 记入报告「未覆盖项与风险」，**禁止伪造通过**。
> **[门禁] 执行驱动 skill 的报告落盘章节不适用**：本领域产出路径固定为 `{artifact_dir}/test-report.md`（见 §七）。

## 二、上游输入与结论有效性前提

### 2.1 读取上游

`read_file("{upstream}")` —— 恒为 `{artifact_dir}/test-plan.md`（计划者是固定前置角色，必定产出）。

| 校验项（[门禁] 输入校验） | 缺失 / 异常时的动作 |
|--------------------------|---------------------|
| `test-plan.md` 存在且非空 | **阻塞**：`send_message` 向 test-planner 请求补全 |
| `{upstream}` 非文件路径（异常路径，如 PM 未按流程传参） | **阻塞**：`send_message` 请 PM 补拉 `test-planner`；**不得把用户原始需求当计划直接开跑**（那等于绕过「用例解析」与「计划确认」两道门禁） |
| 计划已获**用户确认**（含确认记录 / 确认时间） | **阻塞**：`ask_followup_question` 请用户确认后才开工 |
| `bundleName` 与被测版本已明确 | **阻塞**：直接 `ask_followup_question` 问用户，**不得臆测** |
| 用例集（如有）条数与计划一致 | **阻塞**：向 test-planner 报告差异 |

> **[门禁] 上游读取边界——禁止默认回读用例源文件**：执行输入只取 `test-plan.md`（细节不足时可补读同目录 `test-cases.md`）；**不得因「保真复核」等理由主动回读 CSV / Excel 等原始用例源文件**。仅当上游文档存在**缺失 / 含糊 / 自相矛盾**，且无法通过 `send_message` 问 planner 或 `ask_followup_question` 问用户解决时，才回读源文件核对，并在报告中留痕「回读原因 + 差异结论」。

### 2.2 被测物来源与新鲜度（[门禁] 不编译）

| 来源 | 判定 | 动作 |
|------|------|------|
| **A. 设备已装（默认路径）** | 用户未提供 HAP，或明确要求测设备上已装版本 | **跳过安装**；取设备已装版本作为「被测版本」，**标注「新鲜度未校验」** |
| **B. 有 HAP 产物** | 用户提供了 HAP 路径 | ① 校验新鲜度：`stat` 取 HAP 构建时间，与源码最近改动时间对比；② 安装；③ 复核安装后版本 |

> **[门禁] 本领域不编译**：HAP 早于源码改动（或只有 HAP、无源码无法比对）→ **记录 HAP 构建时间**并把时间差告知用户，请其提供最新 HAP；**不得自行编译、不得默认它是新的**。
> **只有 `-unsigned.hap`** → 需用户提供已签名包（签名属构建侧，不在本领域）。
> **安装后必须强制重启进程**（`install -r` 不保证杀进程，否则跑内存旧代码、产出"看似正常却已过期"的结论）——具体命令见 `ai-team-dev-pt-hm-env` E4。

## 三、逐条执行与独立取证（[门禁] 四步不可省）

**默认串行**：同一时刻只跑一条用例。真机通常只有一台，且用例间共享登录态 / 进程 / 日志缓冲——并行会让断言看到别人的界面、日志与操作对不上号。

| # | 动作 | 说明 |
|---|------|------|
| 1 | **清日志缓冲** | 否则日志与本次操作无法对应（命令见 `ai-team-dev-pt-hm-env` E4） |
| 2 | **恢复该条前置** | 进入指定页面 / 账号 / 数据；前置不满足**不得开始断言** |
| 3 | **驱动链路** | 按执行驱动 skill 的「等待策略」轮询等待目标节点，**禁止连续盲操作** |
| 4 | **抓证据并判定** | 节点树 / 请求 URL / 日志标记；未出现预期即判定失败，抓日志定位 |

- **批次规则沿用计划**：环境破坏类用例（断网 / 清数据 / 杀进程 / 切账号）**最后集中执行**，执行后必须恢复环境并复核
- **[门禁] 断言优先用节点树而非截图**（文本可断言、token 成本低）；**通过项不截图**——节点树 / 日志 / 请求 URL 已足以留证；截图仅用于两类场景：① 缺陷取证；② 需目视判断的视觉类结论（配色 / 布局 / 遮挡等）
- **截图动作的对外说明必须注明取证性质**：默认写「截图 {对象} 留证（不读取截图）」；若该次确需读取截图做视觉断言，说明中须明写「将读取截图比对 {具体视觉点}」——避免用户误以为 AI 在解析截图内容、徒增隐私与 token 疑虑
- **[门禁] 未覆盖不得写成通过**；抓到的请求 URL 是「接口参数是否真实下发」的唯一硬证据

## 四、与用户协同（执行期）

协作判据、选项规范、交互模板**见 `ai-team-qa-tool-workflow` §二**（含环境异常总表：未连接 / 多设备 / 未授权 / 未安装 / 锁屏 / 遮挡 / 需登录态 / 需断网）。本扩展只补执行期三条：

| [门禁] | 规则 |
|--------|------|
| 环境异常先走总表 | 按 `ai-team-qa-tool-workflow` §二 逐项给选项问用户；**不得用「环境不支持」直接结束测试** |
| 口头确认 ≠ 条件已生效 | 用户答「已完成」后**必须按客观方式复核**（断网看网卡无 `inet addr`；设备看设备列表）；不通过 → 回告实测结果，再给「重试 / 跳过」 |
| 环境破坏类必须恢复 | 断网 / 切账号 / 清数据执行完必须恢复并复核，未复核不得收口 |

> **非用例内干扰**（营销 / 升级 / 引导弹窗）：关闭后继续跑，**不报缺陷、不中断、不计入用例结果**；关不掉且进不了用例目标页 = **链路中断** → 停测 + 产出阶段性总结 + 给选项问用户下一步。

## 五、缺陷登记

发现失败项按 `ai-team-qa-tool-workflow` **§四 缺陷单必备字段** + **§五 等级定义** + **§六 复现路径写法**逐条落单：

| [门禁] | 规则 |
|--------|------|
| 无证据不得升 P0 / P1 | 只有主观描述 → 先补证据或标「偶现 + 待补充证据」 |
| 复现路径不得省略 | 从应用冷启动后的初始状态写起，逐步骤带操作对象 |
| 等级按「用户能否完成目标」判 | **不按「修起来难不难」判**；有异议按判据重新比对并写明理由 |
| 证据写法 | 按 `ai-team-qa-tool-workflow` §7.1（相对路径文本即链接） |

> **产品缺陷不在本领域修复**：缺陷写入报告并反馈用户 / 对应开发角色；本领域**不修改产品代码**。

## 六、结果回填与产物验证

逐条回填（**先记原始观测，不做结论化表述**）：

| 列 | 要求 |
|----|------|
| 用例 ID / 标题 | 引用 `test-plan.md` |
| 实际执行步骤 | 实际做了什么（含定位方式）；与计划不一致时说明原因 |
| 实测结果 | 节点树片段 / 请求 URL / 日志标记 |
| 结论 | 通过 / 失败 / 未覆盖（**必须写原因**） |
| 证据位置 | **缺陷必附截图链接**（`[evidence/xx](evidence/xx)`）；通过项**不附截图**，写节点树 / 日志 / 请求 URL 关键观测即可；关键日志文件可留链接 |

**[门禁] 收尾校验**：恢复日志级别；断网类用例复核网络已恢复；环境破坏类用例复核已还原。任一项未复核 → **不得收口**。

## 七、产出报告

> 产出前显式加载 `use_skill ai-team-tool-report`（统一元信息模板 + 写入路径），**仅本步骤加载**。

写入 `{artifact_dir}/test-report.md`（**覆盖**基座与执行驱动 skill 的落盘路径），结构与必填项按 `ai-team-qa-tool-workflow` §三 报告结构 + §四 缺陷单字段：

- 元信息（含 `状态: 编辑中|定稿`、`版本: v{N}`、被测版本含构建时间、设备 serial）
- 测试范围与依据（含**未覆盖范围及原因**）
- 执行汇总（总数 / 通过 / 失败 / 阻断 / 未覆盖 + 缺陷按等级分布 + **明确结论**）
- 用例执行明细 + 缺陷详情 + 未覆盖项与风险 + 结论与建议
- **明细表轻量化（[门禁]）**：通过项只写「执行路径 + 结果简述 + 结论」，**不设截图证据列、不逐项贴截图链接**；截图链接只出现在「缺陷详情」与需目视判断的视觉类结论处；关键日志 / 请求 URL 等文本证据不受此限，可留链接
- 证据存 `{artifact_dir}/evidence/`，报告中每条证据**必须写成 `[evidence/xx](evidence/xx)` 形式的可点击 Markdown 链接**（`[路径](同一路径)`，写法细则见 §7.1），**禁止裸路径文本**

> **[门禁] 结论必须明确**：通过 / 有条件通过（列条件）/ 不通过；**禁止「基本没问题」**；存在未修 P0 / P1 时结论只能为「不通过」或「有条件通过」。
> **[门禁] 用户协同留痕**：记录「谁做的 / 为什么 / 共几次」，供复盘。

## 八、置信度评估

在基座检查清单之外追加（每项 10 分，计入清单总分）：

| # | 检查项 | 得分 |
|---|--------|------|
| +1 | 计划内每条用例均有结论（通过 / 失败 / 未覆盖，无遗漏） | 0 / 10 |
| +2 | 每条结论均有可复核证据（节点树 / 日志 / 请求 URL / 截图路径） | 0 / 10 |
| +3 | 未覆盖项集中列出且写明原因（**未覆盖未计入通过数**） | 0 / 10 |
| +4 | 被测版本与新鲜度状态已在报告写明 | 0 / 10 |

> 追加后清单满分相应上调，主观补充仍为 40 分；阈值不变（≥ 85% 放行）。

> **[门禁] 完成信号必须携带**：报告 `状态`（编辑中 / 定稿）、`版本 v{N}`、**`未闭环问题数: {n}`**。
> 本领域 `未闭环问题数` = 报告中「待澄清 / 待用户裁决」项数（**产品缺陷不计入**——它属交付结论的一部分）。**n > 0 → 不算完成**。

## 跨角色沟通协议

| 情形 | 动作 |
|------|------|
| 计划缺失 / 与用例集不符 | `send_message` → `planner-agent` 请求补全，**不自行编造用例** |
| 环境 / 前置条件需用户操作 | 直接 `ask_followup_question` 问用户（按 `ai-team-qa-tool-workflow` §二），**不绕 PM** |
| 链路中断（干扰关不掉、进不了目标页） | 停测 + 阶段性总结 + `ask_followup_question` 给选项问用户下一步；**不静默结束** |
| 与其他角色无法达成共识 | 报 PM（由 PM 汇总向用户提问） |
| **[门禁] 返工必须登记** | 每次重跑 / 修订报告 → 在报告更新对应行「轮次」；**未登记 = 未发生**（`global-rule` §十一 11.3） |
| **[门禁] 超限即停** | 同一 issue 轮次达 3、或报告问题清单条目达 5 → **立即停止往返**，由你 `ask_followup_question` **直接问用户**裁决（`global-rule` §十一 11.4） |
