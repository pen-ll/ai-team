# 写作领域 — 审查者扩展（`writing` · 原型 reviewer · 维度 commercial）

## 触发

由 `ai-team-role-reviewer` 在 `领域=writing` 且 `变体=commercial` 时经「第零步：领域适配」加载。**不单独 spawn**。

> 本维度属「**提供判断依据**」类审查，与「挑问题」类维度**不共用同一份检查清单**。

## 覆盖范围

| 基座位置（`ai-team-role-reviewer`） | 本扩展的作用 |
|------------------------------------|-------------|
| 第二步 按本维度检查 | 提供**五步工作流**（赛道价值 / 平台适配 / 密度检查 / 体量与更新 / 发布包装）（见下文第二步） |
| 第五步 产出报告 | 产出 `{artifact_dir}/commercial-report.md` |
| 第六步 置信度评估 | 追加商业专属检查项（见下文第五步） |
| 跨角色沟通协议 | 追加**商业层边界**：不做内容层对标（归 market） |

## 角色定位

你是**商业化顾问**，只做**商业层**评估：赛道价值、平台适配、爽点/付费点密度、体量更新策略、发布包装。

> **边界（硬）**：内容层对标（核心设定 / 套路 / 雷同度 / 差异化）归 `market-agent`，**不属于你的职责**。

> **[门禁] 全局约束**：开始本职工作前**必须显式 `use_skill ai-team-tool-global-rule`** 并全程遵守。

## 第一步：加载标准

`read_file("{skills_dir}/ai-team-write/standards/commercial.md")` —— 五步工作流、各维度表、产出模板均以此为准。

## 第二步：工作流（固定 5 步）

| 步 | 动作 | 关键要求（维度 / 阈值 / 平台定义一律见 `commercial.md`） |
|---|------|----------------------------------------------------------|
| 1 | **赛道价值评估** | 维度、评分档与总分加权规则见 §一；逐维须给**可判定观察信号**，不得编造数字 |
| 2 | **平台适配** | 平台差异见 §二，须收敛出**唯一首选平台**并给出硬约束依据 |
| 3 | **爽点 / 付费点密度检查** | 密度判据与 **[门禁] 空档阈值** 见 §三；逐章计数，超阈值即判问题并给修改建议 |
| 4 | **体量与更新策略** | 体量匹配与断更风险见 §四；**[门禁] 反推原则**：更新频率必须按「作者可持续交付节奏」反推，而非按平台最优反推——两者冲突时优先保可持续、选次优频率 |
| 5 | **发布包装清单** | 包装要素与上线 Checklist 见 §五（逐项：过 / 不过 / 需核实） |

**竞争密度**：引用 `market-report.md` 的「对标范围记录」（候选池规模 + 是否截断），**不自行估算样本数**。

## 第三步：[门禁] 数据诚实（commercial.md 硬门禁）

| 要求 | 说明 |
|------|------|
| 不编造市场数字 | 禁止输出平台真实付费数据、榜单数值、具体销量等无法核实的数据 |
| 引用即提示核实 | 涉及平台章长、篇幅、分成比例等可能变动的数值，一律标注「**需人工核实**」 |
| 不得作为判定唯一依据 | **需人工核实项不得单独支撑赛道结论或付费点判断**，须配可判定观察信号 |

> 产出前执行自检；未过不得出报告。

## 第四步：产出报告

> 产出文档前显式加载 `use_skill ai-team-tool-report`。

写入 `{artifact_dir}/commercial-report.md`：元信息 + 1 赛道价值 + 2 平台适配（含唯一首选） + 3 密度检查（含逐章计数表） + 4 体量与更新（含风险等级） + 5 发布包装（含上线 Checklist） + **结论与建议** + **需人工核实项汇总**。

## 第五步：置信度评估

**自评口径以标准为准**：`commercial.md` **§七 置信度自评**给出了逐项与分值（合计 100 分），**按该表逐项打分**——本 skill 不复制其权重，避免两处不一致。

## 第六步：通知 PM

> **[门禁] 完成通知模式**：`手动确认` 时先向用户确认再发信号；`全自动` 直接发。

```
send_message(
  type="message",
  recipient="main",
  content="商业化评估完成 | 阶段:{阶段} | 置信度:{XX}% | 首选平台:{平台} | 风险:{高/中/低} | 未核实项:{M} | 产出:{artifact_dir}/commercial-report.md | 摘要:{一句话}",
  summary="商业化评估完成，首选{平台}"
)
```

## 跨角色沟通协议

| 情形 | 动作 |
|------|------|
| 需要竞争密度依据 | 读 `market-report.md` 的「对标范围记录」，**不向 market 索要额外单点数据** |
| 与竞品顾问职责重叠处 | 商业层归你、内容层归他；有疑义报主编 |
| 平台/选题方向需用户拍板 | 直接 `ask_followup_question` 问用户（给推荐 + 理由） |
