# 测试流程与产出规范

> **职责边界**：本 skill 定义「**流程怎么走、怎么与用户协同、结果怎么记**」。
> 用例解析与计划见 `ai-team-qa-tool-testcase-plan`；执行编排与取证见 `ai-team-qa-role-runner`；平台手段见 `platform-map.md` 的环境事实 / 执行驱动列。

## 触发

| 条件 | 说明 |
|------|------|
| 需标准流程 | 端到端规范化测试流程 |
| 需与用户协同 | 环境 / 前置条件需用户操作，要向用户发起选项 |
| 执行结束出报告 | 用例跑完需产出总结报告（含「能否交付」结论） |
| 需规范缺陷单 | 发现缺陷需按等级 / 复现路径 / 证据落单 |

## 一、规范化测试流程（端到端）

| # | 阶段 | 输入 | 动作 | 输出 | 门禁 |
|---|------|------|------|------|------|
| 1 | 用例接入 | 用例原文档 / 清单 | 解析为规范化用例集 | `test-cases.md` | 回读校验条数一致 |
| 2 | 制定计划 | `test-cases.md` | 标执行手段 / 判定方式 / 批次 / 前置 | `test-plan.md` | 计划经用户确认后才执行 |
| 3 | 环境准备 | 计划中的环境要求 | 设备 / 账号 / 数据 / 版本就位 | 环境记录 | 前置不满足不得开始断言；环境异常按 §二 问用户 |
| 4 | 执行取证 | `test-plan.md` | 逐条执行 + 每条独立取证 | 执行记录 | **按计划串行**；未覆盖不得写成通过 |
| 5 | 缺陷登记 | 失败项 | 按 §四 / §五 落单 | 缺陷清单 | 无证据不得升 P0 / P1 |
| 6 | 回归验证 | 修复后的版本 | 重跑受影响项 + 关联项 | 回归记录 | 修复声明不等于已验证 |
| 7 | 总结报告 | 上述全部 | 按 §三 汇总 + 给交付结论 | `test-report.md` | 结论必须明确，禁止「基本没问题」 |
| 8 | 收尾 | — | 恢复设备 / 环境状态 | — | 环境破坏类用例必须复核恢复 |

## 二、与用户协同（[门禁] 一律给选项问用户）

**核心原则**：凡「环境 / 前置条件不满足」且 AI 无法自行消除、或用户一步就能完成而 AI 要绕很多步 → **优先用选项请用户做**；**不得静默跳过、不得硬扛、不得伪造结果**；用户无法配合 → 记为「未覆盖 + 原因」。

**判据（满足任一即问用户）**：

| 判据 | 例 |
|------|-----|
| 用户成本 ≤ 一步操作（点一下 / 切开关 / 看一眼） | 关 Wi-Fi、点一次授权弹窗、解锁屏幕、肉眼确认视觉遮挡 |
| AI 完成需 ≥3 步工具调用，或依赖脆弱定位 | 用坐标点系统设置页、用脚本模拟登录切换 |
| AI 完成有高风险 / 不可逆 | 改设备全局设置、卸载清数据、切换登录态 |
| 环境 / 前置不满足且 AI 无法自行消除 | 未连接设备、连了多台、未授权、应用未安装、锁屏… |

| 不适用（不得推给用户） |
|------------------------|
| 读代码 / 跑命令 / 抓日志 / 写报告 —— 本职，再繁琐也自己做完 |

### 2.1 选项规范（所有 `ask_followup_question` 适用）

| # | 规则 |
|---|------|
| 1 | **业务选项完整展示**：skill 中列出的选项原样全出，**不得截断 / 合并 / 筛选 / 缩减** |
| 2 | **[门禁] 末位统一追加自定义项**：文案固定「**自定义填写（选此稍后补充）**」，`multiSelect: false`；**各 skill 不自行列出该选项**，调用时统一补在末尾 |
| 3 | 自定义项措辞必须让人明白「选中后 AI 会追问具体内容」—— 选项本身不可输入；**禁止**写成「（如：___）」这类暗示可当场输入的措辞 |
| 4 | **选了自定义项但没给具体内容 → 必须追问一次**，不自行猜测 |
| 5 | `options` **只用纯字符串数组**，**不用** `{label, description}` 对象格式（嵌套引号易解析失败）；需补充说明就**用括号拼进选项文本**（如 `"改用模拟器（比真机快）"`） |
| 6 | **数量以业务完整为准**（无硬性上下限）；仅设安全上限 **50**，异常膨胀时才精简 |
| 7 | AI 判断有明显遗漏时可**酌情增补**选项；但**不得替用户筛掉** skill 列出的业务选项 |

### 2.2 交互模板（一问一确认，不反复打扰）

| 项 | 要求 |
|----|------|
| 问题 | 写清「**要你做什么 + 为什么建议你来 + 我这边要绕哪些路 + 做完怎么恢复**」 |
| 选项 | 业务选项全出（见 2.1），末位自定义项统一追加 |
| **[门禁] 问了必校验** | 用户答「已完成」后**必须按客观方式复核**（如断网看 `ifconfig wlan0` 无 `inet addr`、设备看 `hdc list targets`）；不通过 → 回告实测结果，再给「重试 / 跳过」选项 |
| **[门禁] 必须恢复** | 需恢复的环境（断网 / 切账号 / 清数据）**执行完必须恢复并复核**，未复核不得收口 |
| 转交留痕 | 报告记录「谁做的 / 为什么 / 共几次」，供复盘 |
| 同类合并 | 一轮存在多个待用户操作项 → **合并成一次询问**，不逐项反复打断 |
| 不越界 | 不得用「环境不支持」直接结束测试 —— 先走完协同，实在不可为才记未覆盖 |

### 2.3 环境异常处置总表（情况 → 检测 → 处置）

**[门禁] 通用原则**：凡「环境 / 前置条件不满足」且 AI 无法自行消除 → **一律用选项问用户**；**不得静默跳过、不得硬扛、不得伪造结果**；用户无法配合 → 记为「未覆盖 + 原因」。

| # | 情况 | 检测 / 现象 | 处置 |
|---|------|-------------|------|
| 1 | 未连接设备 / 掉线 | 设备列表为空或 `[Empty]`；执行驱动报 `No active devices found...` | 问用户：`["我已连接设备，继续执行", "改用模拟器", "跳过真机测试（记为未覆盖）"]` |
| 2 | 连了多台设备 | 设备列表多行 | **问用户选目标设备** → 后续命令全部加 `--device <serial>` |
| 3 | 未授权 / 未允许 USB 调试 | 设备弹出授权提示；命令报权限类错误 | 请用户在设备上点「允许」→ 重新确认设备列表 |
| 4 | 锁屏 / 息屏 | 启动返回 `10106102` | 先唤醒设备；仍锁屏 → 问用户 `["我已解锁，继续执行", "跳过该用例（记为未覆盖）"]` |
| 5 | **应用未安装** | 启动报 `failed to start ability` | 请用户提供 HAP 或按其指示安装；装不上见 #7 |
| 6 | **设备上装的是旧版** | 行为与源码不符，或无法确认 | **不查版本，直接覆盖**：安装 → **强制重启进程** → 启动（命令见环境事实 skill） |
| 7 | 安装失败（签名 / 空间 / 其它码） | 安装返回错误码 | 只有 `-unsigned.hap` → 问用户要**已签名包**；其它码 → **原样记录报错并问用户**，不猜成因 |
| 8 | 前台被其它应用 / 弹窗遮挡 | 节点树不是目标应用 | ① **非用例内干扰（营销 / 升级 / 引导弹窗）→ 关掉后继续跑**，不报缺陷、不中断、不计入用例结果；② 系统弹窗 / 权限框 → 请用户关闭；③ **关不掉且进不了用例目标页 = 链路中断** → 停测 + 阶段性总结 + 问用户下一步 |
| 9 | 权限 / 授权弹窗 | 节点树出现授权控件 | 请用户点「允许」（**自动化不可代点**）；复测前提示用户在设置中撤销授权 |
| 10 | 需断网 / 弱网 | 用例要求验证失败态 | 按执行驱动 skill 的网络状态类章节执行（mock 优先 → 协同断网 → 记录未覆盖；**执行序放最后、收尾必须恢复并复核**） |
| 11 | 需登录态 / 指定账号 | 目标页面进不去 / 节点树出现登录引导 | 用选项请用户**在设备上**登录目标账号（**未登录不得继续该用例**）→ **[门禁] 登录后必须客观复核**（节点树出现账号态文案或目标页面可达）→ 通过后**自动续接**原用例；不通过 → 回告实测结果，再给「重试 / 跳过」 |
| 12 | 需特定后端数据 | 数据不可构造 | 记为「未覆盖 + 数据不可构造」，**禁止伪造通过** |
| 13 | CLI / 能力探测失败 | 执行驱动能力探测不过 | 按环境事实 skill 升级 / 换包；仍不可用 → 走降级通道并记录降级原因 |
| 14 | 应用崩溃 / 闪退 | 日志出现 `jserror` / `Exception` | **不是环境问题** → 属缺陷，按 §四 落单（通常 P0 / P1） |

**[门禁] 问了必校验**：用户答「已完成」后**必须按客观方式复核**（设备列表 / 网卡状态 / 节点树），不通过 → 回告实测结果，再给「重试 / 跳过」选项。

> **同类合并**：同一轮存在多个环境问题 → **合并成一次询问**（一次说明全部待用户操作项），不逐项反复打断。
> **选项写法**（业务选项全出 / 末位自定义项 / 纯字符串数组）见 §2.1 —— 本表只给业务选项，不含自定义项。
> **越界禁止**：不得用「环境不支持」直接结束测试 —— 先按本表逐项走完（含与用户协同），实在不可为才记未覆盖。

## 三、报告结构

| 章节 | 必填内容 |
|------|----------|
| 元信息 | 测试类型 / 被测版本（含构建时间）/ 环境（设备 serial、系统版本、账号）/ 用例来源 / 执行时间 |
| 测试范围与依据 | 依据文档 + 覆盖范围 + **未覆盖范围及原因** |
| 执行汇总 | 用例总数 / 通过 / 失败 / 阻断 / 未覆盖 + 缺陷按等级分布 + **结论** |
| 用例执行明细 | 逐条 ID / 结论 / 证据位置 |
| 缺陷详情 | 按 §四 字段逐条落单 |
| 未覆盖项与风险 | 项 / 原因 / 风险 / 建议 |
| 结论与建议 | 交付结论（通过 / 有条件通过（列条件）/ 不通过）+ 遗留风险 |

> 骨架见本 skill 同目录 `templates/test-report.md`，可直接复制填写。

## 四、缺陷单必备字段

| 字段 | 要求 |
|------|------|
| 缺陷 ID | `BUG-{序号}` |
| 标题 | `[{模块}] {现象} + {触发条件}`，一句话可判断，不写「有问题」「异常」 |
| 等级 | 按 §五 判定 |
| 模块 / 版本 / 环境 | 版本须含**构建时间**（避免测的是旧包） |
| 前置条件 | 账号 / 数据 / 网络 / 特殊状态 |
| **复现路径** | 按 §六 写法，**不得省略** |
| 实际结果 | 观测到的现象（原文照录，不美化） |
| 预期结果 | 用例 / 需求给出的预期，注明出处 |
| 复现率 | `{成功复现次数}/{总尝试次数}` |
| 证据 | 截图**路径链接**（写法见 §7.1）/ 日志时间点 + 关键字 / 请求 URL / 节点树片段 |
| 影响范围 | 受影响用户与功能 |
| 线索（可选） | 可疑位置（供定位），**不得当作结论** |
| 状态 | 待修 / 已修待验 / 已验通过 / 挂起（挂起须写原因） |

## 五、缺陷等级定义

| 等级 | 名称 | 判据 | 典型例 | 处置 |
|------|------|------|--------|------|
| **P0** | 致命 / 阻断 | 主流程不可用、崩溃、数据丢失或错误、安全漏洞 | 启动即崩、登录失败、提交后数据丢失 | 立即停止测试并上报，修复后才继续 |
| **P1** | 严重 | 核心功能不可用但有绕行，或高频路径受阻 | 列表加载失败、关键操作报错 | 本轮必须修复 |
| **P2** | 一般 | 非核心功能异常、边界未处理、体验明显受损 | 空态文案错误、分页偶发重复 | 本轮或下轮修复 |
| **P3** | 轻微 | 不影响功能完成 | 文案错别字、间距 / 图标偏移 | 记录，不阻塞交付 |

**判级原则**：

| 原则 | 说明 |
|------|------|
| 按「用户能否完成目标」判 | **不按「修起来难不难」判** |
| 按最坏后果判 | 同一现象在弱网 / 边界数据下后果更重 → 取更重等级 |
| 证据不足时降级 | 无法复现且证据不足 → 不得判 P0 / P1，标「偶现 + 待补充证据」 |
| 等级可复议 | 对等级有异议时 → 以判据重新比对，**改等级须写明理由** |

## 六、复现路径写法（[门禁]）

要求：**从应用冷启动后的初始状态写起**，逐步骤带操作对象；任何人照此可独立复现。

```text
前置：{账号 / 数据 / 网络状态 / 已进入的页面}
1. 启动 App，进入「首页」
2. 点击「＋」进入新建页
3. 不输入任何内容，点击「保存」
实际：{观测到的现象}
预期：{用例 / 需求给出的预期}（出处：{用例 ID / 需求章节}）
复现率：3/3
```

| [门禁] 禁止 | 正确做法 |
|-------------|----------|
| 省略前置条件 | 前置必写；无特殊前置写「无」 |
| 写「操作一下」「进入相关页面」这类模糊步骤 | 步骤必须具体到可点对象（文案 / 位置） |
| 只写「偶现」了事 | 写复现率 + 已尝试的触发条件组合 |
| 步骤与证据对不上 | 步骤编号与截图 / 日志时间点一一对应 |

## 七、证据留痕规范

| 类型 | 要求 |
|------|------|
| 截图 | 存 `{artifact_dir}/evidence/`，命名 `{缺陷ID}-{序号}-{说明}.png`；画面必须包含可判断现象的部分（含错误提示原文） |
| 日志 | 给**时间点 + 关键字 + 原文片段**，不贴全量日志 |
| 请求 / 响应 | 抓到的 URL（含 query）与响应作为「参数是否真实下发」的直接证据 |
| 节点树 | 界面断言类结论用节点树片段（可断言、省 token），优先于截图 |

| [门禁] | 说明 |
|--------|------|
| 无证据不得升 P0 / P1 | 只有主观描述 → 先补证据或降级为待确认 |
| 未覆盖 ≠ 通过 | 未覆盖项统一进「未覆盖项与风险」，禁止计入通过数 |
| 证据与结论分离 | 截图 / 日志只是证据，须给出「与预期逐条比对：达成 / 未达成」的结论 |
| 失效重跑 | 证据产生后被测版本又变更 → 受影响结论必须重跑或标注失效 |

### 7.1 证据在报告中的呈现（[门禁]）

| # | 规则 |
|---|------|
| 1 | **不内嵌图片**：报告中不出现 `![]()`、`<img>`、base64 |
| 2 | **路径文本即链接**：每条证据写成 `[证据相对路径](同一相对路径)` —— 链接文字就是路径本身，点击由查看器打开该文件 |
| 3 | **相对路径 + 正斜杠**：路径相对**报告文件所在目录**（形如 `evidence/{文件名}`），不含盘符 / 家目录 / 绝对路径 / `file://` —— Windows、macOS、Linux 同一套写法 |
| 4 | **不写死文件名**：规范只定「证据放在报告同级 `evidence/` 下 + 按上方命名规则产出」；文件名由执行期真实产出决定，**AI 按实际存在的文件填充路径**，不得预设不存在的文件 |
| 5 | **不复重字段**：截图只在缺陷的「证据」字段出现，**不另设「现象截图」行**；同一张图被多条缺陷引用时各条各写一次路径，不用图号中转 |
| 6 | 默认保存原图；因不内嵌、尺寸无诉求，不生成缩略图 / 裁剪图（确有需要时另存，并同样以路径链接呈现） |

**禁止写法**（实测会被查看器拒绝并降级为原始源码文本）：`file://` 绝对链接；嵌套 `[![图](a)](b)`。

**呈现自检**：报告里应看到**可点的路径文字**。若看到 `[evidence/xxx.png](evidence/xxx.png)` 这类源码文本 → 写法被拒，按规则 2 / 3 改回相对路径；若图片被撑大 → 误用了内嵌，按规则 1 改为链接。

## 八、判定与降级

| 情况 | 处理 |
|------|------|
| 同一现象多处出现 | 合并为一条缺陷 + 记影响用例列表 |
| 缺陷无法复现 | 标「偶现 + 复现率 + 已尝试条件」，**不写「无法复现」了事** |
| 用户不便提供截图 | 用节点树 / 日志替代，并在证据栏标注证据类型 |
| 修复后回归 | 只重跑「受影响项 + 关联项」；修复声明未经验证不得计通过 |
| 缺陷被判定为设计如此 | 记入「待澄清 / 需求确认」，**不擅自关闭** |
| 存在未修 P0 / P1 | 结论只能为「不通过」或「有条件通过（列明条件与责任人）」 |
| 交付压力要求放行 | 如实写明风险与影响范围，由用户决策并留痕「已提示风险，用户确认放行」 |
