# AI 多 Agent 协同 — 流程复盘与自我优化

## 触发

**仅在用户选择复盘后启用**：

| 前置 | 说明 |
|------|------|
| 时机 | **PM 收尾阶段、会话回收（`team_delete`）之前**——角色一旦被回收就再也问不到了 |
| 条件 | 用户对「本次流程是否复盘？」回答「要复盘」（默认「不用」，不打扰） |
| 加载方 | **只有 PM 加载**；角色不自行加载（角色只可在完成信号中**可选**附一句流程问题） |

## 一、PM 收集角色反馈

向**每个仍存活**的角色 `send_message`，内容固定为流程层提问（**不问内容质量**）：

```
流程复盘 | 只谈流程层，不谈内容质量：
① 有无卡住（找不到输入 / 门禁无法判定 / 依赖不明）？
② 有无缺信息（上游产出缺字段 / 参数没传 / 需重复问用户）？
③ 有无多余往返（重复确认 / 走了绕路）？
三种都没有就回「无」。
**【必答】请用 send_message 把结论回给 main（recipient="main"）；结论为「无」也必须回一条。**
```

> **[门禁] 边界**：角色只答**流程层**。内容质量意见（文笔、代码风格、需求取舍、方案优劣）**不属于本复盘**，答了也不采纳——那归审稿人 / 主编 / 用户。
>
> **[门禁] PM 侧兜底（不得无限等待）**：收集是**尽力而为**——发出后若角色在合理时间内未回复，按「未回复」登记并继续（必要时补发一次），**严禁停在收集步骤空等**；报告中如实记录未回复的角色，不得编造其反馈。

## 一.五、反馈确认门禁（用户确认后才进入产出与回收）

> **[门禁] 角色反馈全部回收（或兜底登记未回复）后，必须先 `ask_followup_question` 向用户确认，未经确认不得产出报告、不得执行会话回收。**

**为什么**：角色自述的流程体验可能与用户实际观察到的不一致（角色倾向于自评顺畅）；用户是流程的真实体验者，其观察优先级高于角色自述。

**弹窗内容**（一次 ask，多问同出）：

1. **反馈摘要**：逐条列出各角色反馈要点（含「无」的角色）+ PM 自检结论，**原样呈现、不美化**；
2. **问用户**：
   - Q1「角色反馈与你本次实际观察是否一致？」选项：`["一致，按此产出报告", "不一致，我来补充观察（选此稍后补充）", "本次不产出报告"]`
   - Q2「确认后是否执行会话回收（shutdown + team_delete）？」选项：`["确认回收", "先保留团队"]`（默认「确认回收」）

**用户补充观察的处理**：用户补充的观察点**原样写入报告问题清单**（来源标「用户观察」，优先级由用户口径定，未给则默认 P1），不得因与角色反馈矛盾而丢弃或降权——矛盾时在报告中并列呈现双方口径。

**确认后**：进入第二节自检（若已做则合并）→ 第三节产出报告 → 第四节交付 → 按用户 Q2 的选择执行会话回收。

> **[门禁] 未收到用户确认前**：PM 不得发送 `shutdown_request`、不得 `team_delete`——即使所有角色反馈已回收且报告已写完。用户选「先保留团队」则停在报告交付，等待用户后续指令。

## 二、PM 自检

PM 同步自检（不额外问用户）：

| 自检项 | 判定标准 |
|--------|----------|
| 编排是否合理 | 是否有角色被拉起后无事可做？是否漏了必要维度？ |
| 门禁是否有效 | 是否有角色卡在置信度阈值附近反复迭代？ |
| 参数注入是否完整 | 是否有角色索要过 PM 没传的参数？ |
| 用户兜底是否触发 | 阻塞 / 冲突 / 歧义各触发几次？其中几次本可避免？ |

## 三、产出报告

写入 `{artifact_dir}/optimization-report.md`（元信息与文档规范见 `ai-team-tool-report`）：

```markdown
## 一、本次流程问题清单

| # | 来源 | 类别（阻断 / 缺信息 / 绕路） | 现象 | 建议修正 | 涉及文件 |
|---|------|---------------------------|------|----------|----------|
| 1 | tester 反馈 | 缺信息 | `coder-report.md` 未含接口签名，需回头追问 | 在 coder 报告模板增加「接口签名」必填项 | `ai-team-dev-role-coder` |

## 二、本次流程顺畅项

（一句话列出表现正常、无需改动的环节——用于确认哪些设计是对的）

## 三、建议处理优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 会阻断流程（同一问题本轮已实际阻断过 ≥ 1 次） |
| P1 | 造成多余往返或需人工补救 |
| P2 | 体验问题，可延后 |
```

> **流程通畅时**：仍产出报告，「问题清单」写「本次无」，只保留顺畅项——**不留空文件、不编造建议凑数**。

## 四、交付给用户

PM 向用户展示**建议摘要**（P0 / P1 逐条，P2 只给数量）+ 报告路径——**不复制报告全文**。

> **[门禁] 由用户决定是否采纳**：本 skill **只产出建议，不修改任何 skill 文件、不写 `CHANGELOG.md`**。框架资产的改动由框架维护者审核建议后手工执行，并在 `CHANGELOG.md` 记里程碑级变更。

## 禁止事项

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| 自行修改 skill 文件 | 只写 `optimization-report.md`，由用户 / 框架维护者决定是否采纳 |
| 写入 `CHANGELOG.md` | `CHANGELOG.md` 只记里程碑级变更，由框架维护者手工维护 |
| 在 `team_delete` 之后才收集反馈 | 必须在回收**之前**收集——角色回收后不可达 |
| 未经用户确认就产出报告或回收会话 | 反馈收集完必须先过「一.五 反馈确认门禁」，用户确认后才产出与回收 |
| 让角色评价内容质量 | 只问流程层；内容质量归审稿人 / 主编 / 用户 |
| 编造建议凑条目 | 流程通畅就写「本次无」，不凑数 |
| 用户未选择复盘时加载 | 默认不启用；用户答「要复盘」才加载 |
