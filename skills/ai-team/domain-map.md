# 领域注册表

> `ai-team`（通用编排内核）据此识别用户问题所属领域并路由。
> 命中已注册领域 → 委托对应领域 PM；未命中 → 进入通用动态编排（generic）。

## 注册表

| 领域标识 | 领域名称 | 路由目标 | 触发特征（关键词/信号） |
|----------|----------|----------|--------------------------|
| `development` | 软件开发 | `use_skill ai-team-dev` | 编码、开发、写代码、功能、模块、页面、bug、崩溃、报错、重构、App、小程序、HarmonyOS 等 |
| `writing` | 写作（小说 / 文章） | `use_skill ai-team-write` | 小说、网文、连载、长篇、短篇、文章、写作、大纲、世界观、人设、剧情、伏笔、章节、审稿、投稿、读者反馈 等 |
| `qa` | 软件测试（独立测试任务） | `use_skill ai-team-qa` | 按用例验证、跑用例、执行用例、真机测试、UI 自动化测试、测试计划、测试报告、缺陷单、回归验证、验收测试 等 |
| `generic` | 通用动态编排 | 内核内置流程 | 未命中任何已注册领域的复杂问题（写作、策划、调研、决策分析、方案评审等） |

## 触发协调（`development` vs `qa`）

两个领域的触发词存在交叠（都涉及"测试"），按下表判据区分，**不得两处都接**：

| 判据 | 归属 |
|------|------|
| 有**编码/改动代码**诉求（写功能、修 bug、重构），测试只是其中一环 | `development`（其「测试验证」维度覆盖） |
| 用户提供**用例文档 / 用例清单**要求照此验证 | `qa` |
| 用户要求**独立出测试报告 / 缺陷单 / 跑真机 UI 测试**，不涉及改代码 | `qa` |
| 明确说"测一下我刚写的东西" / "验证刚才的改动" | `development`（编码后自验） |

> 判不出时用 `ask_followup_question` 一次问清「本次是**独立测试任务**还是**开发任务的一部分**」，**不猜**。
> `qa` 领域**不编译、不修改产品代码**；用户诉求含改代码 → 告知改走 `development`。

## 使用方式

1. `ai-team` 收到用户问题后，先读取本文件
2. 用「触发特征」列匹配用户意图，命中即路由到「路由目标」列（交叠时按上方「触发协调」判据）
3. 全部未命中 → 按 `generic` 行进入通用动态编排流程

## 新增领域

在表格中新增一行即可，无需改动内核：

```
| {领域标识} | {领域名称} | use_skill {领域 PM skill 名} | {触发特征关键词} |
```

**示例格式**（新增领域时按此结构填写一行）：

| 领域标识 | 领域名称 | 路由目标 | 触发特征 |
|----------|----------|----------|----------|
| `{标识}` | `{领域名称}` | `use_skill {领域 PM skill 名}` | `{触发特征关键词}` |

> **同步要求**：新增领域时，需同步确认该领域 PM skill 已存在且 `autoTrigger` 逻辑不冲突（见 `ai-team/SKILL.md` 的「触发协调」章节）。
